# cysys.dev plan

Status: P0 in progress, 2026-11-19. Decisions are logged in [DECISIONS.md](DECISIONS.md). Nothing is built or deployed yet.

## Goal

1. **The site.** `https://cysys.dev` is the landing page of Cynerdyne Systems Corp: who it is, and a directory of its projects with links to their own domains. Hosted on Vercel.
2. **The house kit.** One source of shared UI (tokens, shadcn/ui components, blocks), design rules, coding procedures and agent skills that any cysys project can pull in.

## Decision: one repository for site and kit; products keep their own

This repository holds the site *and* the kit. Product repositories stay separate and consume the kit by copying versioned items into themselves.

| Option | Verdict | Why |
| --- | --- | --- |
| One monorepo containing every project | Rejected | Each product has its own deploy (the snowmaking dashboard and Schematics run as Compose containers on the owner's VM behind Caddy; this site runs on Vercel), its own domain once it matures, and its own release cadence and history. The dashboard repo is already a workspace monorepo of its own. One repo for everything would couple CI, history and agent context for no shared build; products graduate to their own domains and their repos graduate with them. |
| Site repo + separate design-system repo | Rejected for now | The site is the kit's first consumer and its showcase. One repo lets a component change, its docs page and its live preview land in one commit. Splitting later is a `git subtree split` if the kit outgrows the site. |
| **Site + kit here, products separate** | **Chosen** | Both distribution channels below are built for "a GitHub repo is the source": no package publishing, no version server. |
| Publish `@cysys/ui` to an npm registry | Rejected | Versioning and auth overhead for one maintainer; React-only; forces lock-step. shadcn's copy-in model lets a product (e.g. makesnow.info's Eldora themes) diverge on purpose. |

### How projects consume the kit

| What | Channel | Consumer command | Pinned in the consumer by |
| --- | --- | --- | --- |
| Tokens, components, blocks, config files, `AGENTS.md` fragments | shadcn registry: `registry.json` at this repo's root ([GitHub registries](https://ui.shadcn.com/docs/registry/github)); also built to `https://cysys.dev/r/{name}.json` | `npx shadcn add @cysys/<item>` or `npx shadcn add lewismatt/cysys-dev/<item>` | `components.json` (`registries.@cysys`); upgrades via `shadcn diff` |
| Agent skills (procedures) | [skills CLI](https://github.com/vercel-labs/skills): `skills/<name>/SKILL.md` | `npx skills add lewismatt/cysys-dev` | `skills-lock.json` |
| Always-on rules | `AGENTS.md` fragment shipped as a registry item | `npx shadcn add @cysys/agents-base` | the copied file |

Rule of thumb (Vercel's own guidance): anything an agent must obey on every task goes in `AGENTS.md`; anything task-specific (e.g. "add a page to a cysys site", "ship a release") is a skill.

A cysys project without React (server-rendered pages, a static container) takes the stack-neutral items: `tokens.css` (plain CSS custom properties), fonts, the `AGENTS.md` base, and skills. Components are React only.

## Layout

A single Next.js app at the root, no workspace tooling. `registry.json` must sit at the root for GitHub registries, and `skills/` at the root is what the skills CLI discovers.

```text
app/                    Next.js App Router: landing, /projects, /kit (live docs for every registry item)
components/ui/          shadcn primitives the site itself uses
registry/cysys/         kit source: tokens/, ui/, blocks/, agents/  (what consumers get)
registry.json           kit catalogue (shadcn registry schema)
public/r/               generated by `shadcn build`; served at cysys.dev/r/*.json
skills/<name>/SKILL.md  cysys procedures, installable with `npx skills add`
content/projects.ts     typed project directory that drives the landing page
docs/                   PLAN.md, DECISIONS.md, DESIGN.md (brand and token rules)
AGENTS.md               rules for agents working in this repo
```

## Design model

- **Two-tier tokens.** cysys primitives (palette, type scale, radius, motion) feed shadcn's semantic variables (`--background`, `--primary`, …, OKLCH, Tailwind v4). A product re-skins by overriding semantic variables only; it never edits primitives.
- **Endorsed brands.** cysys is the house style for the landing page and for tools without their own identity. A product with its own brand (makesnow.info) keeps it and carries a small "A Cynerdyne Systems project" mark from the kit.
- **The homage.** Original art and type only. No Cyberdyne Systems logo, film stills, film typefaces or quotes as branding; those are StudioCanal's marks.

## DNS (P4)

`cysys.dev` is on Namecheap DNS. Today the apex, `www`, `snow` and `schematics` all point at the owner's VM. Change only the apex and `www` records to Vercel's values; keep the nameservers at Namecheap so the VM subdomains do not move. If the VM's Caddy has a `cysys.dev` site block, remove it after the cutover so it stops renewing a certificate it no longer serves.
